# 软件需求规格说明（SRS）核心章节

> 命题：数学建模论文评审与优化服务平台 ｜ 赛道：8 · 校园电子商务（以小组锁定的赛道编号为准） ｜ 团队：待补充

## 1. 引言

### 1.1 项目背景

- **项目名称**：数学建模论文评审与优化服务平台
- **所属赛道**：8 · 校园电子商务
- **团队名称**：待补充
- **背景**：高校数学建模集训中，论文反馈主要依赖教师人工批改（周期长、难排队）或通用 AI 问答（评语笼统、无原文定位、修改后无复核）。本平台面向参赛学生、指导教师和校内竞赛组织者，把「论文导入 → 七阶段评审 → 证据定位 → 优化建议 → 人工复核 → 修改稿复审」组织为一条可追溯的服务流程，作为校园电子商务服务按次与套餐提供。
- **首版范围**：单篇/批量评审闭环与模拟订单；获奖等级预测依赖真实历史奖项标签，作为后续可验证扩展，不承诺预测准确率。

### 1.2 术语定义

| 术语 | 定义 |
|---|---|
| SRS | 软件需求规格说明（Software Requirements Specification） |
| FR / NFR | 功能性需求编号 / 非功能性需求编号 |
| 评价量表 | 由评价指标、权重和评分说明组成的评审标准，发布后冻结版本 |
| 证据块 | 带稳定编号及页码/段落定位的论文原文片段 |
| 七阶段 | 问题识别→问题表述→假设→模型构建→求解→代码实现→结果分析 |
| Finding / Claim / Obligation | 评审发现 / 主张 / 该主张应满足的义务 |
| 证据等级 | NOT_CHECKED→DERIVED→EXECUTED→VERIFIED→INDEPENDENTLY_VERIFIED→EXTERNALLY_VALIDATED |
| 复审 | 对修改稿重新评审，并逐条检查历史问题的解决状态 |
| 双轨评分 | 官方量表评分与通用诊断评分分开计算与展示 |
| 待人工核实 | 证据不足时对结论的强制标记，不允许生成无依据强结论 |

## 2. 功能性需求

### 2.1 用户管理

- **FR-01 用户与团队登录**（学生、教师、运营人员，优先级高）：账号+验证码注册，支持高校学号快捷登录；按角色授予论文、量表、任务、报告的访问权限；支持团队授权，成员可共享评审资料但各自保留操作留痕。
- **异常行为**：账号不存在、验证码错误、无权限访问他人资料时给出明确提示；密钥与敏感信息不在页面和日志中明文回显。

### 2.2 核心业务（8 条，满足≥6）

**FR-02 论文批量导入与解析**（学生、教师，高）：上传 PDF/DOCX 或批次文件，系统校验格式、计算 SHA-256 指纹、按标题/段落/表格分块解析并生成证据块索引；失败文件保留错误记录，不创建无效任务。输入：论文文件、赛题信息；输出：资产记录、解析状态、错误提示。

**FR-03 评审服务选择与任务创建**（学生、教师，高）：选择基础诊断、深度评审或团队套餐，绑定论文与已发布量表创建评审任务，生成订单与服务状态。首版采用模拟订单。输入：服务类型、论文、量表；输出：任务编号、订单/服务状态。

**FR-04 评价标准管理**（教师、运营，高）：创建、编辑量表，校验指标权重，发布后冻结版本，评审只能绑定已发布版本。输入：指标、权重、评分说明；输出：已发布量表版本。

**FR-05 七阶段论文评审**（学生、教师，高）：按问题识别→问题表述→假设→模型构建→求解→代码实现→结果分析七阶段生成阶段结果、进度与评分候选，官方与通用诊断双轨评分。输入：冻结论文资产、量表、模型配置；输出：阶段结果、进度、评分候选。

**FR-06 任务队列与进度管理**（学生、教师、运营，高）：展示等待/运行/完成/失败状态，支持刷新、失败重试与单阶段重跑；重跑后下游过期结果标记为 stale，避免混用不同版本资产和量表。输入：任务操作、重试请求；输出：状态、进度、错误信息。

**FR-07 评审问题与证据定位**（学生、教师，高）：将 Finding、Claim、Obligation 与页码、段落或证据块绑定，可查看原文与判断理由；证据不足时标记「待人工核实」，模型提交的强结论自动降级。输入：问题编号、证据引用；输出：原文定位、证据说明、待核实标记。

**FR-08 优化建议生成与人工复核**（学生、教师，高）：依据评审问题生成修改动作、优先级与验收方法，支持人工编辑并保留版本历史。输入：Finding、目标维度、人工意见；输出：建议清单、编辑记录。

**FR-09 修改稿复审与报告导出**（学生、教师，高）：上传新版本论文，匹配历史任务逐条检查旧问题解决状态并做版本对比，导出 Markdown/JSON 评审报告。输入：修改稿、历史任务；输出：解决状态、版本对比、报告文件。

### 2.3 数据管理

复用并细化 FR-02（论文资产指纹）、FR-04（量表版本）、FR-09（报告导出与版本对比），另补充：

**FR-11 数据备份与恢复**（运营，中，[AI补充]）：支持论文资产、量表、任务、审计记录的导出备份与恢复，文件按版本管理，防止误删与版本漂移。

数据规则：论文、量表、任务、证据、建议、报告全部保留版本与关联关系；模型密钥加密存储，主密钥文件需人工备份。

### 2.4 统计报表

**FR-10 统计报表与运营审计**（教师、运营，中）：按时间/服务类型/量表统计任务量、各阶段平均耗时、失败率、订单量与模型调用量；提供建议生成轨迹与系统审计时间线，支撑答辨证与可解释性。输入：查询条件、筛选；输出：统计报表、审计记录。

## 3. 非功能性需求

### 3.1 性能（NFR-01）

- 普通页面操作与任务提交确认 **响应时间 ≤ 2s**（含鉴权、上传校验、状态查询）。
- 完整 AI 评审为 **异步任务**，页面显示排队/分析/核验/完成/失败进度，不套用 2s 时限；端到端耗时与并发能力以真实样例测量确定，不预设未验证的指标。

### 3.2 安全（NFR-02）

- **登录验证**：账号+验证码注册登录，支持学号快捷登录；按角色与团队授权控制论文、量表、任务、报告访问。
- **数据加密**：模型 API 密钥加密存储、不明文回显；敏感数据经 TLS 传输；密钥文件需人工备份。
- **防篡改与审计**：状态机门禁 + 事件账本，模型不能自行推进评审状态；证据不足不得生成强结论。

### 3.3 可用性（NFR-03）

- **移动端适配**：页面支持桌面与窄屏，导航可折叠，弹窗可键盘关闭；
- 解析失败、模型超时、证据缺失等异常均有明确状态与下一步操作提示；
- 任务失败可重试，操作可逆可回滚。

### 3.4 补充（AI 辅助扩充，供审查）

- **NFR-04 可追溯性（[AI补充]）**：评分、Finding、建议编辑、复审与模型调用均保留来源、版本、耗时与审计记录，可供回溯。
- **NFR-05 兼容性（[AI补充]）**：输入支持 PDF/DOCX/Markdown，导出支持 Markdown/JSON，兼容主流浏览器。
- **NFR-06 可恢复性（[AI补充]）**：单阶段失败可重试，下游过期结果标记 stale，避免混用不同版本资产和量表。

## 4. Demo 原型

### 4.1 页面清单与导航关系

| 页面 | 名称 | 内容说明 |
|---|---|---|
| P1 | 首页/入口页 | 项目介绍、服务套餐、上传入口、历史记录、登录 |
| P2 | 提交与任务页 | 上传论文、选择量表与服务、确认模拟订单、任务进度 |
| P3 | 结果与复审页 | 问题列表、原文证据、优化建议、修改稿复审、报告导出 |

**导航关系**：`P1 →（登录/选择服务/上传）→ P2 →（创建任务/查看进度）→ P3`；P3 可发起「提交修改稿复审」回到 P2 的上传流程，形成版本复审闭环。

### 4.2 核心交互流程描述

1. P1 选择服务套餐并登录，进入 P2。
2. P2 上传论文（PDF/DOCX），选择赛题与已发布量表，确认模拟订单并创建评审任务。
3. P2 查看任务从排队→分析→核验→完成/失败的状态变化，失败可重试。
4. 任务完成进入 P3：按七阶段查看得分与问题列表。
5. 点击某条 Finding → 展开页码、原文证据块、判断理由；无证据时显示「待人工核实」。
6. 根据建议修改论文，在 P3 提交修改稿 → 系统追溯历史问题显示「已解决/未解决」与版本对比。
7. 导出 Markdown/JSON 评审报告。

每个核心交互均对应至少一项 FR：登录→FR-01，上传→FR-02，下单→FR-03，量表→FR-04，评审→FR-05，进度→FR-06，证据→FR-07，建议→FR-08，复审/导出→FR-09。
