# 核心用例说明

> 说明：以下 5 个用例的主事件流由小组人工编写。`[AI补充]` 仅表示 AI 提出的候选替代流，后面的“人工审查”记录最终处理结果。

## UC-001 上传并解析论文

- **参与者**：学生、教师
- **前置条件**：用户已登录，且拥有论文上传权限。
- **后置条件**：论文资产保存成功并进入解析完成或解析失败状态。
- **主事件流（人工编写）**：
  1. 用户选择 PDF、DOCX 或 Markdown 文件。
  2. 系统检查文件大小和格式。
  3. 系统计算文件 SHA-256 指纹。
  4. 系统按页码、段落或行号解析文本。
  5. 系统生成证据块索引并展示解析状态。
- **替代流**：
  - 2a. 文件格式不支持：系统提示支持的格式，结束用例。
  - 2b. 文件超过大小限制：系统拒绝上传并提示压缩或拆分文件。
  - 4a. 文档无法解析：系统保留失败记录，提示用户更换文件或人工处理。
  - 4b. `[AI补充]` 论文存在扫描图片但无文本层：人工审查后保留，系统应提示 OCR 未完成，不将空文本当作论文内容。

## UC-002 创建评审任务

- **参与者**：学生、教师
- **前置条件**：论文资产已解析完成；系统存在已发布量表。
- **后置条件**：创建评审任务，绑定论文资产、量表版本和服务类型。
- **主事件流（人工编写）**：
  1. 用户选择论文资产。
  2. 用户选择基础诊断、深度评审或团队评审服务。
  3. 用户选择已发布的评价量表。
  4. 系统展示输入摘要和任务配置。
  5. 用户确认创建任务。
  6. 系统冻结输入指纹并生成任务编号。
- **替代流**：
  - 3a. 量表未发布：系统禁止创建任务并提示先发布量表。
  - 4a. 论文资产在选择后发生变化：系统要求刷新并重新确认版本。
  - 5a. 用户取消确认：系统不创建任务，保留当前页面配置。
  - 5b. `[AI补充]` 任务创建时模型配置缺失：人工审查后保留，任务可以创建，但启动评审时应进入“待配置”或失败状态。

## UC-003 执行七阶段论文评审

- **参与者**：学生、教师、模型服务
- **前置条件**：评审任务已创建，论文和量表输入已冻结，模型配置有效。
- **后置条件**：七阶段结果保存，任务进入完成、降级或失败状态。
- **主事件流（人工编写）**：
  1. 系统读取冻结的论文、证据目录和量表。
  2. 系统依次执行问题识别、问题表述、假设、模型构造、求解、代码实现和结果分析。
  3. 模型服务返回结构化阶段结果。
  4. 系统校验证据 ID、定位和阶段字段。
  5. 系统保存阶段分数、理由、Finding 和证据引用。
  6. 系统更新任务进度。
  7. 七阶段均完成后，系统生成诊断总分并进入待证据审计状态。
- **替代流**：
  - 3a. 模型返回格式错误：系统记录失败阶段，允许重试，不接受无效结果。
  - 3b. 模型调用超时：系统记录安全错误信息并将任务标记为可重试。
  - 4a. 证据 ID 不存在或定位不稳定：该阶段降级为待人工核实。
  - 5a. 单阶段失败：已完成阶段保留，任务进入降级状态。
  - 5b. `[AI补充]` 模型把推测当作确定结论：人工审查后保留，系统必须把结论降级为 `INCONCLUSIVE` 或 `CONDITIONAL`。

## UC-004 查看证据与优化建议

- **参与者**：学生、教师
- **前置条件**：评审任务至少存在一个阶段结果。
- **后置条件**：用户查看问题、原文证据和可执行建议，可编辑建议。
- **主事件流（人工编写）**：
  1. 用户打开评审任务详情页。
  2. 系统展示阶段进度、诊断分数和 Finding 列表。
  3. 用户选择一条 Finding。
  4. 系统展示 Finding 的严重级别、结论、理由和证据引用。
  5. 用户打开证据定位，查看页码、段落或证据块原文。
  6. 系统展示对应优化建议和验收方法。
  7. 用户保存人工修改后的建议。
- **替代流**：
  - 4a. Finding 没有稳定证据：系统显示“待人工核实”，不显示强结论。
  - 5a. 证据块已被标记 stale：系统提示重新运行相关阶段。
  - 7a. 建议缺少验收标准：系统提示补充验收方法后再保存。
  - 7b. `[AI补充]` 用户尝试把 Finding 直接改为已解决：人工审查后删除，解决状态必须通过修改稿复审产生。

## UC-005 提交修改稿复审并导出报告

- **参与者**：学生、教师
- **前置条件**：存在历史评审任务，用户拥有修改稿上传权限。
- **后置条件**：生成新资产版本，展示历史问题解决状态，并可导出报告。
- **主事件流（人工编写）**：
  1. 用户在评审结果页选择“提交修改稿复审”。
  2. 用户上传修改后的论文文件。
  3. 系统解析修改稿并生成新的资产指纹和证据块。
  4. 系统将新版本与历史评审任务关联。
  5. 系统重新执行必要阶段并匹配历史 Finding。
  6. 系统展示每条问题的已解决、部分解决或未解决状态。
  7. 用户选择 Markdown 或 JSON 格式并导出报告。
- **替代流**：
  - 3a. 修改稿解析失败：系统保留原任务和原版本，提示重新上传。
  - 4a. 系统无法可靠匹配版本：要求用户手动确认关联关系。
  - 5a. 历史 Finding 找不到新版本证据：标记为待人工核实。
  - 7a. 报告生成失败：保留复审结果，允许稍后重新导出。
  - 7b. `[AI补充]` 修改稿页数明显减少：人工审查后保留为提示信息，不自动判定论文质量下降。

## AI 补充替代流审查结论

| 编号 | AI 建议 | 人工处理 | 理由 |
|---|---|---|---|
| A-01 | 扫描图片无文本层时提示 OCR 未完成 | 保留 | 属于真实解析边界，不改变人工主流程 |
| A-02 | 模型配置缺失时创建任务但延迟启动 | 保留并调整 | 任务可以保存，但必须明确启动前置条件 |
| A-03 | 模型把推测当作确定结论时降级结论 | 保留 | 符合证据优先和待人工核实规则 |
| A-04 | 用户可直接把 Finding 改为已解决 | 删除 | 会绕过修改稿复审，不符合业务规则 |
| A-05 | 修改稿页数减少自动判定质量下降 | 保留为提示 | 页数变化只能提示人工检查，不能直接推出质量结论 |
