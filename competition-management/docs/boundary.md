# 数学建模比赛管理系统边界分析

## 1. 项目定位

本系统面向校内或校际数学建模赛事，服务赛事组织方、评审专家、指导教师和参赛团队。首版目标是把赛事从发布到归档的关键信息集中管理，降低报名、材料提交、评审分配、结果发布和复核过程中的人工沟通成本。

系统包含两个使用面：

- 赛事组织平台：由赛事管理员维护赛事、题目、规则、队伍、评审任务、结果和审计记录。
- 参赛团队工作台：由队长、队员和指导教师完成报名、材料协作、版本提交、状态查询和结果反馈。

论文评审与优化建议系统暂时保持独立产品边界，不作为本系统首版的内置模块。

## 2. 目标与成功标准

### 2.1 业务目标

1. 让参赛者能够在一个入口完成报名、材料提交和状态查询。
2. 让组织方能够按赛事节点推进审核、评审和结果发布。
3. 让评审专家能够获得明确的评审任务、评分标准和匿名材料。
4. 让每次关键操作都有操作者、时间和对象记录，便于复核与申诉处理。
5. 让赛事结束后可以导出完整结果并归档，而不依赖个人聊天记录或本地表格。

### 2.2 首版成功标准

- 管理员可以创建并发布一个赛事，配置报名、提交和评审时间节点。
- 队伍可以注册、维护成员和指导教师，并在截止时间前提交论文及附件。
- 管理员可以审核报名、分配评审任务、监控进度并处理异常任务。
- 评审专家可以在匿名材料和已发布评分表下完成评分与评语提交。
- 系统可以汇总评分、发布结果、登记申诉并保留审计记录。

## 3. 外部参与者

| 参与者 | 主要目标 | 与系统的关系 |
|---|---|---|
| 赛事管理员 | 配置和推进赛事 | 管理赛事全生命周期和权限 |
| 评审专家 | 独立完成论文评审 | 接收任务并提交评分、评语 |
| 指导教师 | 指导队伍并查看授权信息 | 绑定队伍、查看提交和结果 |
| 队长 | 代表队伍完成报名和提交 | 管理队伍成员、版本和提交 |
| 队员 | 参与资料准备和协作 | 查看队伍任务并提交协作材料 |
| 通知/邮件服务 | 传递报名、评审、结果通知 | 外部消息通道，可选接入 |
| 文件存储 | 保存论文和附件 | 外部存储依赖，可由本地存储替代 |

## 4. 系统边界

### 4.1 系统内

- 赛事创建、编辑、发布、暂停和归档。
- 赛事规则、时间节点、公告、题目和附件管理。
- 用户、队伍、成员、指导教师和评审专家的赛事内身份管理。
- 报名申请、资格审核和队伍状态管理。
- 论文、代码、数据说明和其他附件的上传、版本管理与提交锁定。
- 评审专家管理、评审任务分配、匿名材料展示和评分提交。
- 评审进度监控、逾期提醒、任务替换和复核登记。
- 成绩汇总、排名、获奖名单、结果发布和通知。
- 申诉、复核、操作日志、数据导出和赛事归档。

### 4.2 系统外

- 真实身份认证、学校统一身份平台和支付系统。
- 论文内容本身的学术正确性判断；系统只管理评审流程和评审结果。
- 评审专家最终的专业判断和组织方的裁决责任。
- 外部邮件、短信、即时通讯平台的具体送达能力。
- 代码运行、数据运行和模型复现实验环境。
- 获奖概率预测和跨赛事成绩预测。
- 全国性赛事的分赛区、复杂并发调度和跨机构监管。

### 4.3 首版明确不承诺

- 不保证评分等同于最终获奖结果。
- 不自动执行参赛队伍上传的代码或数据。
- 不把论文评审 AI 的建议直接作为最终成绩。
- 不在首版实现完整的在线支付、商业套餐和多租户计费。
- 不承诺扫描件、复杂公式、图表和压缩包内容都能被完整解析。

## 5. 赛事生命周期

```text
草稿 → 报名开放 → 报名截止 → 资格审核 → 比赛进行中
→ 材料提交 → 提交截止 → 评审中 → 结果待发布
→ 结果发布 → 申诉/复核 → 已归档
```

每个阶段由管理员控制，系统在截止时间、提交状态和评审状态上提供校验。只有管理员可以推进赛事阶段；关键阶段迁移必须记录原因和时间。

## 6. 组织端与团队端职责边界

### 6.1 赛事组织端

赛事管理员负责赛事配置、规则发布、报名审核、评审任务调度、异常处理、结果发布和归档。评审专家只访问被分配的匿名材料和评分表。管理员可以查看全局进度，但必须通过审计日志追踪对成绩和任务的修改。

### 6.2 参赛团队端

队长负责队伍注册、成员维护、指导教师绑定和最终提交。队员负责协作材料和版本准备。指导教师只能查看被授权队伍的信息。团队端无法修改赛事规则、评审任务、成绩和其他队伍的数据。

## 7. 数据与权限边界

- 赛事数据按赛事 ID 隔离，用户只能访问自己有权限的赛事对象。
- 评审阶段对评审专家隐藏队伍身份和非必要联系信息。
- 提交截止后，论文版本和附件默认锁定；重新提交必须符合赛事规则并留下记录。
- 成绩修改、评审任务替换、申诉处理和结果发布属于高风险操作，需要记录操作者、原因和前后值。
- 文件访问使用任务和赛事范围校验，下载链接不应暴露永久公开路径。
- 用户身份、论文内容、联系方式和评审结果属于敏感数据，导出和归档应受权限控制。

## 8. 主要风险与约束

- 赛事规则和时间节点变化会影响报名、提交和评审状态，必须允许管理员修订并记录版本。
- 评审任务可能逾期、拒绝或因专家冲突需要替换，系统必须支持异常恢复。
- 论文和附件可能包含恶意文件、隐私或超大内容，需要文件类型、大小和访问控制。
- 评审结果争议需要可追溯的评分、评语、复核意见和修改日志。
- 真实通知通道、身份认证和文件存储可以在后续版本接入，首版保留可替换接口。

## 9. 后续扩展

后续可以增加论文评审与优化建议服务、修改稿复审、跨赛事统计、教师工作台、移动端通知、在线支付和分赛区管理。获奖等级预测必须单独采集真实标签并进行按年份、赛题和队伍隔离的验证。
