# 软件需求规格说明（SRS）核心章节

> 命题：数学建模比赛管理系统 ｜ 赛道：8 · 校园电子商务（以小组锁定的赛道编号为准） ｜ 团队：待补充

## 1. 引言

### 1.1 项目背景

- **项目名称**：数学建模比赛管理系统
- **所属赛道**：8 · 校园电子商务
- **团队名称**：待补充
- **背景**：数学建模赛事的报名、材料提交、评审分配、结果发布和申诉复核往往依赖聊天群、邮件和本地 Excel，信息分散、状态不透明、评审难以匿名、结果难以追溯。本系统面向赛事组织方、评审专家、指导教师和参赛团队，把「赛事发布 → 队伍报名 → 资格审核 → 材料提交 → 匿名评审分配 → 成绩汇总 → 结果发布 → 申诉复核 → 归档」组织为一条可追溯的业务闭环。
- **首版范围**：面向校内/校际规模的赛事组织平台与参赛团队工作台；真实身份认证、在线支付、全国级并发调度不在首版承诺内。

### 1.2 术语定义

| 术语 | 定义 |
|---|---|
| SRS | 软件需求规格说明（Software Requirements Specification） |
| FR / NFR | 功能性需求编号 / 非功能性需求编号 |
| 赛事生命周期 | 草稿→报名开放→报名截止→资格审核→比赛进行中→材料提交→提交截止→评审中→结果待发布→结果发布→申诉/复核→已归档 |
| 匿名评审 | 评审专家只能看到被分配任务的材料，默认隐藏队伍身份和非必要联系信息 |
| 回避关系 | 专家不得评审本人指导、亲属或存在利益冲突的队伍材料 |
| 审计日志 | 关键操作记录的对象、前后值、操作者、时间和原因 |
| 归档 | 赛事结束后导出并冻结为只读状态 |
| 双使用面 | 赛事组织平台（管理员/专家）与参赛团队工作台（队长/队员/教师） |

## 2. 功能性需求

### 2.1 用户管理

- **FR-01 创建与发布赛事**（赛事管理员，高）：创建赛事草稿，配置名称、届次、主办方和时间范围，校验必填项和时间顺序后发布为报名开放状态。输入：赛事基础信息、时间范围；输出：赛事草稿/已发布赛事。

### 2.2 核心业务（含创新点，14 条）

- **FR-02 配置规则与时间节点**（赛事管理员，高）：配置报名、提交、评审和申诉时间节点与规则，校验时间不冲突，发布规则版本后用户端看到当前有效规则和时间表。
- **FR-03 发布题目与公告**（赛事管理员，高）：绑定赛题、附件和公告到赛事，控制可见范围并支持撤回。
- **FR-04 注册队伍与资格审核**（队长、管理员，高）：队长注册队伍并维护成员，管理员审核报名资格，驳回时说明原因。
- **FR-05 上传与管理论文版本**（队长、队员，高）：上传论文及附件，校验格式、大小和截止时间，保留版本并标记当前提交。
- **FR-06 提交、撤回与截止锁定**（队长，高）：截止前可提交、撤回和重新提交；截止后禁止提交，管理员特殊处理必须记录授权原因。
- **FR-07 分配评审任务与回避**（管理员，高）：按专家专业标签和回避关系分配评审任务，检查重复分配，每个任务有状态与截止时间。
- **FR-08 匿名评审与评分提交**（评审专家、管理员，高）：对专家匿名展示材料，专家提交评分与评语，系统校验分值范围和必填项。
- **FR-09 评审进度监控与异常处理**（管理员，高）：汇总待评、进行中、逾期和已完成任务，支持替换专家、延长时限并记录原因。
- **FR-10 成绩汇总与结果发布**（管理员，高）：汇总评分生成成绩，发布获奖名单并向队伍展示结果。
- **FR-11 申诉处理与复核**（管理员、队长，中）：队长提交申诉单，管理员分派、调查、裁决并关闭，保留处理记录。
- **FR-12 操作日志与审计**（系统、管理员，高）：记录成绩、权限、提交和状态变化的对象、前后值、操作者和时间。
- **FR-13 数据导出与赛事归档**（管理员，中）：导出报名、提交、评审、成绩和日志，归档后数据只读。
- **FR-14 团队协作空间**（队长、队员、教师，中）：提供队内协作记录和权限控制，协作内容不影响正式提交版本。

### 2.3 数据管理

- 赛事数据按赛事 ID 隔离，用户只能访问自己有权限的赛事对象。
- 论文版本和附件按版本管理，提交截止后默认锁定。
- 文件访问使用任务和赛事范围校验，下载链接不应暴露永久公开路径。

### 2.4 统计报表

- 可统计报名、提交、评审和结果分布，统计口径和时间范围须可说明。

## 3. 非功能性需求

### 3.1 性能（NFR-01）

- 普通列表、详情和状态查询在常规本地网络下快速返回（页面操作与提交确认响应时间 ≤ 2s）。
- 文件上传和评审生成属于异步任务，界面展示排队、进行中、完成和失败状态。
- 首版面向校内或校际规模，不预设全国级并发指标。

### 3.2 安全（NFR-02）

- **登录验证与授权**：按角色与赛事范围鉴权，最小授权；评审专家默认看不到队伍身份。
- **数据保护**：上传文件进行扩展名、MIME、大小和存储路径校验；密码、密钥和敏感凭据不出现在日志、导出文件或普通接口响应中。
- **审计与防篡改**：成绩、评审意见、申诉和权限修改必须留下不可随意覆盖的审计记录。

### 3.3 可用性（NFR-03）

- **移动端适配**：页面支持桌面与窄屏，导航可折叠，弹窗可键盘关闭。
- 上传中断、评审超时和通知失败应显示可恢复状态。
- 管理员可以查看任务失败原因并进行重试或人工处理。

### 3.4 补充（AI 辅助扩充，供审查）

- **NFR-04 可追溯性（[AI补充]）**：赛事状态迁移、评审任务替换、成绩修改和申诉处理均保留版本与审计记录。
- **NFR-05 兼容性（[AI补充]）**：浏览器端兼容主流浏览器，导出支持 CSV/JSON，通知通道支持站内并预留外部接口。
- **NFR-06 可恢复性（[AI补充]）**：评审任务逾期、拒评或冲突时支持替换与延期，归档后关键记录只读不清空。

## 4. Demo 原型

### 4.1 页面清单与导航关系

| 页面 | 名称 | 内容说明 |
|---|---|---|
| P1 | 首页/入口页 | 赛事列表与状态公示、登录入口、报名入口、发布赛事入口 |
| P2 | 赛事管理/报名提交页 | 赛事配置、队伍报名、材料上传、版本与截止锁定、评审分配 |
| P3 | 评审与结果页 | 匿名评审任务、评分提交、进度看板、成绩汇总与发布、申诉与审计 |

**导航关系**：`P1 →（登录/选择赛事/报名）→ P2 →（创建赛事/上传提交/分配评审）→ P3`；P3 可发起「成绩发布」「申诉处理」「导出归档」回到 P1/P2，形成赛事全生命周期闭环。

### 4.2 核心交互流程描述

1. P1 登录并选择赛事，进入报名或管理入口。
2. P2 管理员创建/发布赛事并配置时间节点与规则；队长报名并上传论文与附件。
3. P2 查看提交截止前的版本与提交状态，截止后锁定。
4. P2/P3 管理员按回避关系分配匿名评审任务。
5. P3 评审专家查看匿名材料并提交评分、评语。
6. P3 管理员监控评审进度，处理逾期/拒评任务。
7. P3 成绩汇总并发布获奖名单，队伍查看结果并可提交申诉。
8. P3 导出 CSV/JSON 并归档为只读。

每个核心交互均对应至少一项 FR：登录→FR-01，建赛→FR-01/FR-02/FR-03，报名→FR-04，上传→FR-05/FR-06，分配→FR-07，评审→FR-08，监控→FR-09，发布→FR-10，申诉→FR-11，审计→FR-12，归档→FR-13。
